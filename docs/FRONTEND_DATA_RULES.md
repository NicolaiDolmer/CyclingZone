# Frontend server data
SSOT for the incremental #6494 migration. Draft implementation; Claude reviews the issue spec before merge.

## Ownership and scope
- Migrated market pages import typed data hooks from `frontend/src/data/`; their UI owns filters, dialog state and pending interaction feedback.
- One lazy browser QueryClient is shared by migrated routes and remains mounted for browser focus/reconnect events. The public landing/prerender import graph does not load Query. Server runtimes are created separately and never share private data.
- Private query keys contain auth generation, viewer, team, resource and relevant parameters. Tokens and e-mail addresses never enter keys. Real viewer/team changes cancel and clear old queries. Same-viewer token refresh preserves generation.
- Unknown auth blocks private reads. The viewer-scoped team bootstrap precedes team-scoped reads. Cached team data remains available after a background failure; initial bootstrap failure terminates loading and exposes retry.
- Reads use AbortSignal where supported and reject late results after scope/write revision changes. Writes bind to the captured viewer, never retry automatically, cancel older reads and hold new reads until writes settle. Money and successful bids remain server-confirmed.
- Query freshness is 30 seconds and inactive retention five minutes. No polling, persistence, broadcast cache, service-worker data cache or offline write queue is added.

## Market resources
- `marketData.ts` owns listings, sent/received/archived offers and swaps, shape validation and ability normalization.
- `auctionData.ts` owns one canonical snapshot for auction rows, current bids/proxies, watchlist and squad availability. `auctionRealtime.ts` synchronously applies whitelisted committed server fields before UI callbacks. Unchanged joins/private fields survive; changed relationship IDs clear stale joins and reconcile the exact auction key. A known bidder with a pending name shows the existing skeleton, never a false no-bids label. Unknown names have one scope-bound lookup per id.
- Pure price/end updates, foreign terminal rows and unrelated foreign bids cause no new reads. Unknown membership/insufficient payloads reconcile only the auction key in leading bounded 400ms windows. Own bid INSERTs additionally reconcile that key to confirm private proxy/budget state; a public bid amount is never treated as a proxy ceiling. Own terminal settlement also reconciles the exact bootstrap-team key. Cash remains explicitly pending until the necessary fresh server reads succeed; cancellation/reverted data cannot confirm it. A runtime-scoped uncertainty control marker survives cold owner disposal even before any snapshot exists; it contains no rows/private amount guesses and clears only on confirmed receipts or generation/viewer/team change. Failed reconciliation stays pending across remount and can be retried. Monetary requests await reconciliation before entering the existing write barrier; no price is deducted optimistically.
- Public delta/name/uncertainty publications preserve the combined snapshot's existing dataUpdatedAt: they do not make private context artificially fresh or suppress focus recovery. Full snapshots, including focus/reconnect and existing post-write refreshes, finish under market traffic with an ordered per-read server-delta journal. Older unowned reads are cancelled on the exact key before publishing a patch. The journal is cleared when its reads finish/abort or its owner is disposed. Scope generation/viewer/team and disposal epochs fence async results; same-viewer token refresh preserves the owner. Callbacks receive the actual pre-patch cached row, rather than a previous React frame.
- After first migrated route use, existing profile listing readers delegate through `sharedRequestCache` into the same Query listing key. Exact credential snapshots are checked before reuse. Existing listing mutations invalidate this owner through the existing service; unrelated legacy GET caches keep their owners.
- Watchlist optimism updates the canonical cache and rolls back only the affected rider; reads are cancelled before it changes and reconciled after the write.
- API transport preserves existing 401 handling, Retry-After, cancellation and network errors. Errors and malformed bodies never become successful empty arrays. Known data remains visible on failed refresh. An initial settled Retry-After/unauthorized waiting state is distinct from active loading: it keeps a quiet canonical placeholder and the existing manual retry action. No automatic retry timer is added; transport still enforces Retry-After.

## Incremental boundary
Dashboard is still legacy at the first checkpoint and must not be called migrated. Cross-cutting profile, active-season, scouting, player flags and existing self-fetching widgets retain their named legacy owners until separately migrated; do not wrap their existing memo caches in a second Query cache.
New data modules/tests are TypeScript. Bundle ceilings remain unchanged. No new recurring service cost.
