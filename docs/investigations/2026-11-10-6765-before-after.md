## Final behavior and failure modes

With ranking_shadow_decoupled_6765 ON, all five legacy refreshes and coordinator finish run before shadow maintenance. Maintenance stays inside the same local queue slot, so a queued legacy follow-up cannot race its SQL writer lock. The released legacy token/version is never reused: the established unleased budget leaves remaining work for later ticks. Legacy failures and cooldown retain queued shadow maintenance. Deferred/unavailable returns outside queue ownership attempt a reserve pass only with atomic idle admission; a busy queue skips it and leaves durable backlog for later ticks. No reserve job replaces pending legacy work or acknowledges failed legacy work. OFF/missing/error keeps the frozen legacy path. No reader swap, planner changes, activation or production writes.

An independent review reproduced a queue-slot regression in the first correction: overlapping callers could start the next legacy refresh while unleased shadow held its writer lock. A new deterministic test failed before the queue-slot fix and passes afterward. Review of that fix found no remaining P0/P1. The clean-tick variant also follows queued coordinator admission, and daily parity requires an authoritative clean claim. Its deterministic regression was independently rerun after the fix. This finding is resolved, not deferred.
