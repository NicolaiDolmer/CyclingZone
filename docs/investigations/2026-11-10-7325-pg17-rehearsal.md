## Scope of the fixture

The runner creates a fresh exclusive local cluster, binding only 127.0.0.1.
It creates a synthetic source, pg_dump exports it, and psql restores each scenario
into a separate prefixed database. Production training-plan DDL, sponsor-contract DDL/unique indexes, the balance
audit RPC, and rank-rollover SQL plus its later publication transformation are
loaded unchanged from their owning public repository sources. Other tables are an explicit dependency
subset, not a complete production schema. No live SELECT, dump, credentials or
private data are used.

The production orchestrator and carry-over functions run unchanged. A narrow
SQL transport translates their query calls to separate native psql connections;
unsupported shapes fail. No dependency phase is replaced with a mock. This is
not PostgREST, HTTP routing, RLS, or a complete-schema compatibility proof.
The final runner denies all JavaScript network access before importing backend
modules: fetch, HTTP(S), TCP, TLS, DNS, HTTP/2 and UDP. Legacy dotenv loaders are
bounded by preseeded synthetic local service values, so they cannot restore a live
Supabase target. Native PG binaries use explicit loopback arguments and every SQL
connection verifies its live data directory/version against the ownership marker.
No outgoing messaging configuration or service response is faked to complete a phase.

Interruption calls process.exit only after native mutation completion. Each
resume launches a new Node process against the same database. The source cluster,
SQL copy and evidence are preserved. PG stop uses the owned data directory,
fast graceful shutdown, a 120-second server wait and 150-second process timeout.
