## SSR compatibility

Directly importing an installed Recharts ESM component in Node reproduced
`ERR_MODULE_NOT_FOUND` for an extensionless internal import. Therefore
`frontend/vite.config.js` sets `ssr.noExternal: ["recharts"]`: Vite resolves and
bundles those internal imports for prerendering. This does not affect the
client graph; a final client rebuild reproduced the exact after measurements.

The SSR client counterpart was built separately with `--ssr src/entry-server.jsx`
under the semaphore. A network-prohibited Node smoke check imported the emitted
Tooltip, AdminGrowthPage and SeasonFinanceReportPanel chunks, then rendered
`/` in English, `/help` in English and `/privatlivspolitik` in Danish. All passed.
Because SSR output was required to stay in scratch, the smoke check resolved
its external packages from the worktree's existing frontend cache using a
Node resolution hook. No dependency was installed or copied.

## What caused the dependency-update growth?

The module-attribution build confirms Recharts already resolves to `es6/`.
Its shared emitted graph contains chart selectors, Redux Toolkit, Immer,
decimal arithmetic and D3 scale/time-format code. The library is not being
accidentally loaded through its CommonJS entry.

The pre-#7933 lock hashes to
`39e3fcfbf57a6d44e5ce08e3dd19cfc0f68a1dbe508605516c7d76518f95f818`;
the matching dependency cache is absent on this machine. Installation and
dependency rollback were forbidden for this lane. Thus **a same-source,
old-lock/new-lock byte attribution is not available**. Changes include Sentry,
i18next, Immer, es-toolkit, react-redux, victory-vendor and Rolldown. Their
individual gzip contribution is unknown; no culprit is asserted.

The current import-only reduction is measured causally. It does not explain
the full historical growth, recover the previous budget, or justify lowering
the budget from existing headroom alone.
