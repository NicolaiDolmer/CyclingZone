# Daily rider receipt implementation plan

> Execution: inline in an isolated worktree, using systematic-debugging, test-driven-development and executing-plans. One independent whole-branch review before release.

**Goal:** One honest date receipt across training and rider views, with rider activity details.
**Design-go:** Owner chose A, Rytterkvittering, in this Codex chat on 30/9, after comparing two interactive designs. Existing date-report approval: [design decision 8](../specs/2026-09-29-traen-nu-og-prognose-design.md), issue #5915.
**SSOT:** [TRAINING_RULES](../../TRAINING_RULES.md), [PROGRESSION_RULES](../../PROGRESSION_RULES.md), [PAGE_TEMPLATES](../../design/PAGE_TEMPLATES.md), [TASTE](../../design/TASTE.md).
**Architecture:** A pure typed frontend projection groups immutable training runs by date and rider, retaining ordered activities. The authenticated API adds all current-date runs; its legacy latest-run field remains compatible. History reads are paginated and all training consumers use the same projection. Existing race-day snapshots repair the development display without rewriting player history.

## Constraints and review focus
- No training, balance, condition or historical player-data writes.
- Unknown/partial/reconciliation data never becomes a complete receipt or a measured zero.
- Duplicate runs and repeated responses never double-count gains.
- Initial progress, last recorded abilities and one date-level condition settlement have separate sources.
- Older calendar-day records remain readable; missing metadata is described honestly.
- New frontend modules/tests are TypeScript; dates in tests are explicit.

## Score extension (owner approved to build, 30/9)
Latest documented training-pass score appears in each rider row, with per-pass
quality in the expanded receipt. Desktop adds a column; mobile uses a subline.
The existing visibility flag remains the gate. Ledger identity includes date,
season and race day, with a unique unslotted fallback for legacy reports.
Read-only review caught the legacy metadata difference; its regression was
reproduced and fixed. Score extension: 26 focused tests and 12 final browser
cases passed; the wider affected run passed 37 cases (20 intentional skips).
Release remains owner-gated, and the shared backend must ship the additive
session ledger before preview can display these scores on live team data.
