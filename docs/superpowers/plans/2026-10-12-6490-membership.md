# #6490 membership: sekventiel tilpasning efter A-go

Ejer-go 12/10: https://github.com/NicolaiDolmer/CyclingZone/issues/6490#issuecomment-6118488960.
SSOT: [TRAINING_RULES](../../TRAINING_RULES.md). Bindende
[addendum](../specs/2026-10-12-6490-membership-addendum.md) og den oprindelige
[L1–L5-plan](2026-10-11-6490-training-seen.md), med counter-repræsentationen erstattet.

1. **M1 / revideret L1:** `database/manual/6490/membership/foundation.sql`, testfixture
   og semantik/grants-tests. Pair-PK `(report_id,rider_key)`, separat rider_key-indeks,
   rå strenge, source-markør, statement-triggere og fysisk bevarelse af uændrede refs.
   Gamle rapporter forbliver umarkerede. Ingen FK der ændrer TRUNCATE-kontrakten.
2. **M2 / revideret L2:** samme katalog `parity.sql` + `backfill.sql`, bounded runner.
   Kontrolleret source-lock/SKIP LOCKED, fuld pair-paritet (også forkert report-tilknytning
   med samme samlede count), layout/funktions-/trigger-/ACL-kontrakt, restart/idempotens.
3. **M3 / revideret L3:** medlemskabsbaseret EXISTS og COUNT med eksakte reader-fingerprints,
   legacy rollback, admin recovery og restore efter anonymisering i samme transaktion.
   Opdater de aktive adapters; behold afvisningsgates for delvist/ukendt schema.
4. **L4 igen:** native PG17, alle tidligere cases og begge påviste deadlocks, ekstra
   source-rowkonflikter, roller, reader-cutover og genopbygning. Paritet efter hver case.
5. **L5:** oprindelig kapacitetsplan, både fulde træningskvitteringer og læselast,
   1×/10×, WAL/lager/latens og driftsbevis. Manglende miljø er BLOCKED, ikke grønt skip.

Hver leverance: rød/grøn → uafhængigt read-only review → rettelser → FULL/preflight
via verify-lock (maks 2) → guarded commit/push → draft-PR og issue-handoff → næste.
Hovedagent bygger sekventielt; reviewer gpt-6-astra/high efter repoets modelkontrakt.
Ingen ny generel godkendelse mellem leverancerne. Ingen merge, prod-write eller GIN-drop.

Ruling: ny kandidat har eget `membership/`-katalog; den forkastede counter-kode
bevares som reproducerbart kontrolforsøg, ikke som aktiv vej. Det gør hver leverance
selvstændigt testbar uden halvtilpassede gamle tests. Omkostning: midlertidigt to
tydeligt adskilte forsøgsvarianter; M3 skal gøre runtime-adaptervalget entydigt.

Langsigtet kvalitetskrav: ingen absolut påstand om "bedst" ud fra en prototype.
Primærnøglens report-prefix passer til vedligeholdelsen; rider-indekset til opslag.
PostgreSQL dokumenterer betydningen af indeksenes venstre kolonner og transaktionelle
låse: [indekser](https://www.postgresql.org/docs/17/indexes-multicolumn.html),
[låse](https://www.postgresql.org/docs/17/explicit-locking.html). L5 skal dokumentere
vækstomkostningen ved historiske referencesæt og skelne mekanismebevis fra kapacitet.
Ingen automatisk arkivering, partitionering eller sletning tilføjes uden målt behov.
