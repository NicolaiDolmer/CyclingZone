# P16 shared targets implementation plan

Owner build-go: [7/11 mandate](https://github.com/NicolaiDolmer/CyclingZone/issues/7877#issuecomment-6712966598).
SSOT: `docs/design/TASTE.md` P16 and `docs/design/PAGE_TEMPLATES.md`.

Goal: K1/K2/K3/K6/K8/K11 use real mobile targets of at least 44 x 44 CSS pixels. One PR, Refs #7877; no merge until owner approves the images.

Implementation ruling: reserve static target geometry on phones instead of overlapping invisible rectangles. Padding-only expansion overlaps wrapped FilterBar rows and short Segmented options. Native controls cannot reliably render pseudo hit areas. Fixed-position proxy labels add focus, picker, clipping and scroll risk. Static CSS minima preserve native semantics and refs, require no runtime measurement and never change dimensions on focus/press. Initial density differences will be shown explicitly in the before/after evidence; this is not a claim of pixel-identical layouts.

## Constraints

- Only the six shared roots: LanguageSwitcher, buttonClass, tabClass, MobileColumnChips, Segmented and controlClass.
- Apply at <=640 CSS pixels or with a coarse primary pointer, so a phone retains its targets in landscape. Fine-pointer desktop dimensions stay unchanged.
- Do not touch RiderLink, RiderNameIcon, RiderHoverCard, RiderNameCell or patchNotes.js.
- No player text authored. Patch-note integration remains with Claude/owner before release.
- No dependencies, production data, deploy, flag flip or merge.

## Tasks

1. Capture the five highest-traffic affected pages before the patch: rider profile, dashboard, inbox, race detail, own team, at 375 and 1280 CSS pixels. Synthetic fixtures only.
2. Add browser regressions in a new `.spec.ts`: native field focus/picker semantics, real target dimensions, adjacent controls, mobile inclusive 640 boundary, no interaction-time geometry changes, and unchanged desktop sizes. Observe expected failures first.
3. Apply static 44px minima to the six recipes. Keep variants, fonts, active/disabled semantics, layout containers and desktop classes.
4. Run targeted tests, preflight, lint, unit tests, frontend build and required broad verification behind the shared semaphore. Check forbidden paths remain unchanged.
5. Capture annotated before/after pairs for the five pages in private OneDrive `private-handoffs/pr-shots/7877-p16/`; show any static density change honestly.
6. Independent diff review, guarded commit and immediate push. Open one draft PR. Request HEAD-bound review; handle CI. Mark ready only after required CI is green, retain manual-review and do not merge.

## Review focus

- Inputs and selects keep their native DOM/ref/label contracts.
- Narrow options and wrapped filter rows must not steal a neighbour's pointer input.
- Disabled controls remain disabled; active segments keep their intentional no-op.
- First/last chips and tabs remain reachable by horizontal scrolling and keyboard navigation.
- Focus/press must not alter control dimensions or shift neighbouring controls; initial mobile density changes are explicit evidence for the owner.
