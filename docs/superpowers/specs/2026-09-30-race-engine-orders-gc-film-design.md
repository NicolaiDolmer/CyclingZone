## Product contract
1. A chasing group closes the distance by its own progress. Catching an escape does not move escapees backwards or apply a separate punishment. Ordinary fatigue/terrain may detach them afterwards.
2. Captain/sprint captain/helper need an effective morning-break order. Hunter defaults to attempting; explicit false overrides it for the stage. Free role may act autonomously on normal effort; a break order prioritises the attempt. Save suppresses spontaneous free-role attempts, but an effective break order still permits an attempt with its normal price. Grupetto never attempts. A helper away in an escape cannot simultaneously assist a captain in another group.
3. Formation is contested: permission, paid attempt, rival reaction, possible escape. Do not fill it with riders whose attempts failed. A stage can have no established morning escape. Strong rivals are opposed by actual competing teams, never by secretly reducing their abilities. Successful escape and later survival are separate outcomes.
4. Chase uses available workers; neutral responds to team GC/stage interests. Let-go is passive, with an exceptional limited preventive GC reaction. Stage-win loss alone and one-day races do not trigger that GC exception. Use pre-stage GC gaps, current group progress, relevant abilities/remaining terrain; transient virtual leadership alone is insufficient.
5. The exceptional passive-plan reaction shares one finite work budget per team/stage across pauses, repeated threats and segments. Stop on a contained threat or exhausted budget. Respect rider effort, protect captains, charge actual work once. Explicit chase is not capped by this exception's budget. No guaranteed catch or rescue.
6. Film, report and result markers derive from actual formation/attack/split/catch/finish facts. A failed attempt is not an escape. Passive terrain selection is not a deliberate attack. Show main meaningful events first; no new detailed-film UI or #5101 rider card in this delivery. Ordering within the same kilometre follows causal engine sequence.

## Proposed typed boundaries to review before implementation
Keep simulation pure. Add optional `rules_revision: "legacy" | "orders_gc_v1"` to StageInput, resolved by the runner; default is legacy. Separate shared correctness fixes from the gated policy in named functions; do not retain a second whole engine or silently switch a started race to v3 on a policy-resolution failure.
Add optional `gc_context` with `stage_number`, `leader_id: string | null`, and `standings: readonly { rider_id: string; rank: number; gap_seconds: number }[]`. Adapter reads published pre-stage `leader` rows for active starters, not this stage's results. First-stage ties are explicit, not imaginary previous standings. One-day stages have no GC context. Missing/invalid required data is diagnosed; never substitute zero for an unknown deficit and report successful GC protection.
Use per-stage EngineState to retain a typed team reaction state: idle/reacting/exhausted, accumulated actual work, and a qualitative start/stop reason. Budget accounting is an engine concern; tuning and work amounts stay private and never enter player API/events.
Introduce a single participation-history projection consuming actual typed events: morning-escape membership and caught/survived outcome; later offensive-attack history; passive group moves. Existing group kind alone is insufficient. Renderer and result adapters share this projection. Do not reinterpret old timelines without the evidence needed to classify them.
The exact calibration parameters and approved quality bands remain a separate private decision after paired simulations. Structural invariants can be implemented/tested before those values, but activation is not approved from a regression floor.

## Release routing, proposed technical implementation
Bind tactical regime at the first stage claim, using the existing race claim/lock boundary. Proposed additive `races.engine_rules_revision` field and an atomic server-only resolver: existing started/claimed races receive legacy; newly claimed races receive the approved current revision. Null on a started race means legacy, never automatic opt-in. Do not write this field or a migration to prod without the separate migration/apply approval.
Both regimes share verified correctness in time bookkeeping and truthful rendering. Formation/permissions/dynamic neutral and GC safety belong to orders_gc_v1. Test this mixed deployment explicitly; a fix's effect on times is not a promise to preserve identical future results. UI must show which tactical policy applies before saving.
Reuse a prior regime when resuming/retrying the same first claim. An unknown revision is an observable error, never the newest rules. Pin tuning used for the tactical policy as part of revision discipline. A mere engine_version=4 value in simulation_runs does not pin a patch.
Historical race result rewrites and payouts are outside this package. Correcting historical presentation is allowed only from stored evidence and does not recalculate the race.

## UI/copy proposal
Keep the existing tactics/results/film surfaces and their templates. Suggested EN/DA labels: Chase / Jag; Read the race / Vurder undervejs; Leave the chase to others / Overlad jagten til andre. Passive-plan help explicitly says the team may make a limited response to a serious GC threat, respecting available riders.
Morning escape: existing Flag icon, with participated/caught/survived tooltip. Later attack: a distinct existing stroke icon, labelled Attack / Angreb. No offensive marker for passive split. Never rely on colour alone. Disable/explain the incompatible grupetto attempt before save. A captain on normal without break permission must not be depicted as choosing a morning escape.
The paired desktop/mobile sketch is a proposal, not a screenshot of delivered UI. Approval of the actual preview is needed before UI build; annotated real before/after evidence is needed before merge.

## Work packages and test contract

P1: fix chase time/group bookkeeping and participation history. Prove nearest relevant group vs large tail, catch crossings, multiple groups and post-catch selection; verify passage/final times, film and labels together. Existing passage fix #5914 must remain correct.
P2: gate new role/formation policy by pinned regime. Exercise every role/effort, absent vs false overlay, successful/failed attempts and many/all teams requesting escapes. Workers only aid the group in which they exist.
P3: supply real GC and compute actual rival reactions, including neutral. Exercise first-stage ties, leader attacks, harmless riders far behind, routes and changing gaps, finite resources and per-stage budget persistence. Same implementation for human and AI teams.

Pair seeds/inputs, vary real field composition and tactics; measure attempts, successes, price and GC outcomes separately. Include one-team-chases/all-neutral/all-attempt scenarios.
