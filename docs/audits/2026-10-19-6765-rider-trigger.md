## Off contract

All twelve source triggers skip delta writes while the stage is off/missing or
invalid. Migration/off transitions replace queued work with one rebuild marker.
Enabling always queues repair because off-period changes were deliberately skipped.
On-to-beta changes preserve pending work. This avoids a growing off backlog and
does not silently treat the old shadow as current when later enabled.

Source transactions hold a shared stage advisory lock through commit, including
when skipped while off. A flag transition takes its exclusive counterpart and
the existing processor writer lock using nonblocking try-locks. Busy changes fail
with 55P03 and roll back, so repair cannot run before skipped writes commit.
Normal apply takes the shared stage fence and rechecks the flag in SQL. A stale
Node admission therefore cannot consume/expand the off rebuild marker. SQL parity
also returns disabled while off; Node treats that as deferral, not a mismatch.

Relevant source writes and apply require READ COMMITTED semantics (including PG's
READ UNCOMMITTED alias). Stronger snapshots fail with 40001 and an explicit retry
message rather than silently reading an old flag snapshot. No runtime request for
RR/SERIALIZABLE was found in the repository. Tests cover both rejected levels.

Only service_role can use the explicit p_maintenance=true RPC argument for a
deliberate off-state benchmark. Runtime never sends it. Old RPC overloads are
removed atomically with the new defaults/grants; migration replay remains idempotent.
This maintenance override was not needed for the riders measurements below.

## Riders measurement

NEW.team_id). It references OLD directly and declares no transition tables.
An unchanged team does not schedule the callback. PostgreSQL documents this
[AFTER WHEN behavior](https://www.postgresql.org/docs/17/sql-createtrigger.html).
