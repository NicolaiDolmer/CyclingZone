# Dashboard presence wait exceeded the page budget (#8019 / #8022)

The CLS patch waited for core data, strip presence, dependent race rows, up to five selection requests and the latest result before showing any dashboard content. Equal endpoint latency in the original benchmark concealed the asymmetric case: one slow secondary request held every ready card. A regression test holding only my-latest-result reproduced the missing team heading after 2500 ms on the reviewed build.

The correction uses a single 1500 ms budget from component mount, keeps unknown core values as skeletons and reveals ready fixed cards. Optional modules/dependent rows no longer extend loadAll; dependent entries have an abort signal and selection candidates share one 8 s signal. Stage details reuse localized pending/no-results text. PageHeader owns the opt-in mobile action-row contract. State tests import production helpers rather than executing extracted source.

A late confirmed-empty strip still collapses and valid late conditional data still appears: this trades possible late CLS for bounded access to ready content. Measure one delayed request at a time, actual useful content separately from frame/FCP, and report that tradeoff. Parent owns asymmetric before/after timings, screenshots and full E2E. Patch notes remain an owner-approved proposal in the draft PR, not a published release entry.

Independent review also caught two presence edges: useTodayStages(null) reports an empty settled strip before identity resolves, so the page must pass pending presence while the first team/season lookup is outstanding. PostgREST resolves abort/network errors as error/data:null instead of throwing; check that error before replacing known registrations. Browser regressions reproduced the missing strip and disappearing ongoing race after a network timeout refresh (including the SDK retry settlement).

A caller-only pending override still dropped the strip for one identity-to-hook commit. Frame/DOM sampling reproduced it while the schedule request remained held. The sole hook consumer is Dashboard: the hook now keeps no-identity presence pending/empty, and Dashboard hides the strip only for confirmed no-team. Known refresh data is retained. This removes the transient empty state without a render-time ref or invented data.

The asymmetric screenshot review measured a 50px mobile header collapse: the unknown 192px subtitle wrapped the action cluster, unlike the settled identity. Compact capped identity skeletons and a local pending locked-balance line keep the original row anatomy. An undefined latest result also left its existing grid cell empty; it now shows the shared Card/header and measured pending body (about 356px desktop / 392px mobile against the settled synthetic fixture 355/394; other histories/first-race/empty variants differ). Error/null and confirmed-empty visibility are unchanged. Focused geometry tests reproduce the old 50px header difference and absent result placeholder before the fix. Production-default and E2E bundle branches require separate measurement; earlier uniform-delay evidence does not prove asymmetric CLS acceptance.

The first integrated full E2E attempt was stopped incomplete after #452's active/inactive comparison failed twice. Decoded trace snapshots at its two bounding-box calls showed settled Giro data and no stage strip in both states. The actual 254px difference was NextActions: one settled single-item body retained min-height:312px after loading, while the other had natural height58px because it was ready at mount. The comparison now deliberately holds the same selection request until NextActions reports busy=true, releases it, then awaits busy=false before measuring both variants. Exact y/height assertions remain unchanged; no runtime layout/visibility is changed to satisfy the test. A clean final full E2E run remains required.


Review 2 found that the new request deadlines called AbortSignal.timeout directly, which is absent in supported Chrome 90 and iOS 15. Selection created it outside its try block, allowing the whole dashboard to crash. A shared AbortController/timer helper now provides the deadline without newer static AbortSignal APIs. Request settlement disposes timers; effect cleanup, superseded stage loads and dashboard refresh/unmount abort owned requests. The browser regression deletes AbortSignal.timeout before dashboard mount and checks real stage, selection and latest-result content. No player copy is changed; the patch-note proposal remains parent-owned.


The second review also found that signup, onboarding and Discord presence no longer participated in the initial layout decision after those requests moved off the core load path. Their generation-safe settled flag now joins initialDataReady within the existing single 1500 ms mount cap. Known responses from an older refresh cannot publish or settle a newer one; errors and missing auth settle without inventing card data. Requests beyond the cap still reveal ready dashboard content, and valid late cards remain visible under their existing rules.


A failed finished-stage enrichment is not proof that no result exists. The existing status line now stays empty at its existing minimum height when detailsUnavailable is set. A browser regression waits for enrichment settlement and reproduced the previous false no-results text before checking the empty18px line. Confirmed no-winner responses keep their established no-results behavior.


Known stage details are reusable only while the card state and completed-stage count match.
