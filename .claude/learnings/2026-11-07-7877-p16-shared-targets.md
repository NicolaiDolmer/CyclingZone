# #7877: shared mobile target geometry

- Cause: padding-only shared recipes rendered 22/28/30/32/38/42 px targets despite TASTE P16.
- Fix: static 44 x 44 minima at inclusive <=640px or a coarse primary pointer in the six owning recipes, with fine-pointer desktop recipes preserved.
- Invisible centered hitboxes are unsafe in gapless Segmented controls and wrapped 12px-gap filter rows; native proxy controls also risk caret/picker/ref regressions.
- Regression coverage uses real browser dimensions, native focus/select behavior, disabled controls, neighbour taps and 640/641 boundaries with explicit test time.
- A minimum width replaces flex items' automatic content minimum. Explicit mobile shrink-0 on canonical tabs preserves long English labels and horizontal scrolling; the regression was observed failing before that correction.
- A responsive min-w-11 also overrides a consumer's larger unprefixed minimum. The native-field floor therefore lives in the component layer; a short-option FilterBar regression proved 62px before the correction versus its intended 144px minimum.
- Width alone misses phones in landscape: a coarse-pointer 812px case failed at 30/38/42px before adding the pointer branch. Fine-pointer 640/641 and 1280px desktop checks remain separate.
- Initial mobile density changes are explicit before/after evidence, not hidden as pixel-identical layouts. No merge without owner image-go.
- Player copy/patchNotes.js remain owned by the concurrent Claude work, as explicitly directed by the owner.
