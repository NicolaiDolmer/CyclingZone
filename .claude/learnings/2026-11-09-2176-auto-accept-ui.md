# #2176: counter boundary and editable auction bid

Seller counter/accept mutations did not apply the current listing auto-price boundary. The start handler used expected_price both as the optimistic price version and the opening bid, so an editable larger bid would have been ignored.

The fix separates bid_amount from expected_price, validates the submitted bid through existing purchase/price-band checks and reserves that amount in a service-only atomic start RPC. Legacy RPC signatures remain available. Offer writes have a database boundary trigger; the final transfer claim rechecks under the same team/rider/listing locks as price changes. Supabase trigger errors are handled before success notifications.
