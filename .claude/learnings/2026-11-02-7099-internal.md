# #7099: PostgREST timeout classification

- Owner authorization: 2 November 2026, #7495 comment 6579459364.
- Cause: the log query truncates raw messages to a bucket; the measured
  timeout bucket sometimes includes the start of an appended access-log date.
  Raw bucket comparison therefore reports an existing class as new.
- Regression on unchanged main implementation: three tests failed, including
  false new-class detection and missed aggregate high-volume detection.
- Fix: match only the documented PostgREST timeout plus the complete observed
  truncated date suffix. Aggregate canonical counts before both thresholds;
  normalize both comparison windows identically.
- Negative controls preserve other sources, server failures, meaningful extra
  descriptions and unrelated timestamp formats. Inputs remain unchanged.
- No SQL, API, thresholds, production configuration or player behavior changed.
  No patch note applies. Existing query row-limit behavior remains unchanged.
- Parent owns independent review, CI, #6184 alarm follow-up and final close-out.
