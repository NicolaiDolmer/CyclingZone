First review found a descriptor/ownership gap when fstat failed, and unrecoverable empty/partial markers after process interruption. Both regressions were reproduced before the fix (9 existing passes, 2 new failures).

Ordinary exclusive file creation and writes remain in each actual Git target directory. Each marker is registered immediately; its exact bigint inode/device identity is persisted and fsynced in a v2 private journal before writing marker content. Recovery requires a dead owner, exact branch/worktree, matching file identity and a valid content prefix. All descriptors close in finally; cleanup attempts each owned target independently and retains its journal when incomplete. No ref namespaces/config are pruned.

A process crash between creation and durable identity, an interrupted private journal update, or unavailable identity cannot be safely reclaimed portably. These paths preserve evidence, block future permission proof and require manual inspection. Unknown v1 journals, symbolic replacements, reused/live PID and foreign replacements (including identical content) remain fail closed. Hardlink-only publication was rejected because it would weaken ordinary file creation permission evidence.
